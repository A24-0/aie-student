# HW14 – эмбеддинги, FAISS, оценка retrieval и mini-RAG по базе знаний

## 1. Кратко: что сделано

- База знаний: небольшой набор учебных текстов (ML, оптимизация, CNN, RAG и т.д.), заданных в ноутбуке.
- Чанкинг: разбиение по словам с перекрытием; параметры в коде.
- Эмбеддинги: **sentence-transformers** `all-MiniLM-L6-v2`; индекс **FAISS** `IndexFlatIP` на нормированных векторах.
- Retrieval: контрольные запросы, метрики **hit@k** и **recall@k**; эксперимент с разными `chunk_size`.
- Обновление базы: добавлены новые документы, переиндексация, таблица до/после.
- Mini-RAG: ответ по шаблону из top-k фрагментов с источниками.

## 2. Среда и воспроизводимость

- Python: 3.14.3 (локальная `.venv` в репозитории)
- faiss / faiss-cpu: установленный в окружении (см. `pip list`; для ноутбука достаточно `import faiss`)
- sentence-transformers / transformers / sklearn: см. `pip list` (типично: `sentence-transformers`, `transformers` 5.x, `scikit-learn` 1.8.x)
- torch (если использовался): да (бэкенд ST), 2.11.0
- Устройство (CPU/GPU): CPU или CUDA/MPS в зависимости от машины; расчёт эмбеддингов через ST.
- Seed: 42 (где применимо).
- Как запустить: открыть `HW14.ipynb` и выполнить Run All из `homeworks/HW14/`.

## 4. Retrieval и индекс

### 4.1. Эмбеддинги и индекс

- Какая embedding-модель или способ векторизации использовались: `all-MiniLM-L6-v2`.
- Какая метрика сходства использовалась: скалярное произведение (эквивалент косинуса при L2-нормировке).
- Какой индекс `FAISS` использовался: `IndexFlatIP`.
- Какой `top_k` использовался по умолчанию: 3 (для оценки и mini-RAG).
- Что показали первые примеры retrieval: см. ноутбук и [./artifacts/retrieval_eval.csv](./artifacts/retrieval_eval.csv).

### 4.2. Контрольные запросы и оценка retrieval

- Сколько контрольных запросов использовалось: 8 (в текущей версии ноутбука; при необходимости расширьте до 8–12 по ТЗ).
- Что считалось релевантным ответом: совпадение поля `expected_source` с одним из найденных id источника в top-k.
- Какие метрики retrieval считались: hit@k, recall@k (при одном релевантном документе на запрос они совпадают с долей попаданий).
- Итоговый `hit@k`: см. среднее по столбцу `hit_at_k` в CSV или вывод ноутбука.
- Итоговый `recall@k`: в учебной постановке с одним релевантным документом совпадает с hit@k.
- Дополнительные метрики (если были): опционально MRR — не считался.
- Какие запросы оказались самыми простыми: с прямым совпадением терминов с текстом чанка.
- Какие запросы оказались самыми проблемными: перефразирования и общие вопросы без ключевых слов из базы.

## 7. Анализ

Качество RAG верхне ограничено качеством индекса и чанкинга. Мелкие чанки повышают точность по коротким запросам, но фрагментируют контекст. Обновление базы улучшает покрытие новых тем. Шаблонный генератор не исправляет ошибки retrieval.
