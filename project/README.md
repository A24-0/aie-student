# ФинФакт — RAG-ассистент по личным финансам

## 1. Паспорт проекта

- **Название:** ФинФакт — гибридный RAG-сервис, который отвечает на вопросы по личным финансам со ссылками на источники
- **Автор:** Гришутина Ангелина Валерьевна
- **Группа:** ЭФБО-17-24
- **Контакт:** @A24_AAA

**О чём проект.** Человек задаёт вопрос про вклады, кредиты, налоги, инвестиции и т.п.,
а сервис ищет ответ в собственной базе знаний и возвращает короткий ответ вместе с
документами, на которых он основан. Поиск гибридный: лексический BM25 и семантический
по эмбеддингам объединяются через Reciprocal Rank Fusion. Это снимает типичную проблему,
когда плотный поиск «плывёт» на точных терминах, а BM25 — на перефразировках.

## 2. Структура

```
project/
├── data/            # корпус (corpus.json) и контрольные запросы (eval.json)
├── configs/         # config.yaml + .env.example
├── notebooks/       # 01_eda, 02_retrieval_experiments (выполнены, с графиками)
├── src/
│   ├── data/        # загрузка, чанкинг, препроцессинг для BM25
│   ├── retrieval/   # embedder, dense (FAISS), bm25, hybrid (RRF)
│   ├── rag/         # engine + generator (extractive / опционально LLM)
│   ├── eval/        # метрики hit/recall/mrr/ndcg + прогон оценки
│   ├── tracking/    # лёгкий трекер экспериментов (mini-MLflow)
│   ├── service/     # FastAPI: /health /metrics /search /predict /reindex
│   └── train.py     # сборка индексов + эксперименты
├── tests/           # pytest: метрики, фьюжн, чанкинг, API
├── artifacts/       # индексы и результаты экспериментов
└── Dockerfile
```

## 3. Установка

Нужен Python 3.10+. Модель эмбеддингов (~470 МБ) скачивается при первом запуске.

```bash
cd project
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install --upgrade pip
pip install -r requirements.txt
```

## 4. Запуск

### 4.1. Сборка индексов и эксперименты

```bash
python -m src.train
```

Команда строит FAISS- и BM25-индексы, прогоняет сравнение ретриверов и кладёт в
`artifacts/`: индексы, `retrieval_comparison.csv`, `eval_per_query.csv`,
`experiments.csv` и `training_summary.json`.

### 4.2. Сервис

```bash
python -m src.service.main
```

Поднимается на `http://127.0.0.1:8000`. Если индексов ещё нет, сервис соберёт их на старте.

| Метод | Endpoint | Назначение |
|-------|----------|------------|
| GET   | `/health`  | статус + число чанков |
| GET   | `/metrics` | счётчики запросов и средняя задержка |
| POST  | `/search`  | только поиск документов |
| POST  | `/predict` | ответ + источники (основной endpoint) |
| POST  | `/reindex` | пересобрать индекс без перезапуска |
| GET   | `/docs`    | Swagger UI |

Примеры:

```bash
curl http://127.0.0.1:8000/health

curl -X POST http://127.0.0.1:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"question": "как вернуть налог за обучение"}'

# можно явно выбрать метод поиска и глубину
curl -X POST http://127.0.0.1:8000/search \
  -H "Content-Type: application/json" \
  -d '{"query": "сколько денег держать в подушке безопасности", "method": "dense", "top_k": 3}'
```

### 4.3. Docker

```bash
docker build -t finfact .
docker run -p 8000:8000 finfact
```

Индексы собираются на этапе сборки образа, поэтому первый запрос отвечает сразу.

## 5. Данные

Корпус собран вручную: ~80 справочных текстов по 13 темам личных финансов, без ПДн.
Подробности — `data/README.md`.

## 6. Конфигурация и секреты

Параметры лежат в `configs/config.yaml` (модель, метод поиска, `top_k`, веса RRF,
режим генерации). Секреты и переопределения — через переменные окружения с префиксом
`AIE_` (шаблон `configs/.env.example`). Реальный `.env` в git не попадает.

Режим генерации:
- `extractive` (по умолчанию) — ответ собирается из найденных фрагментов, без внешних сервисов;
- `llm` — если задать `AIE_LLM_API_KEY`, ответ генерирует LLM через OpenAI-совместимый API,
  но при любой ошибке сервис откатывается к экстрактивному режиму.

## 7. Демонстрация на защите

1. `python -m src.service.main`, открыть `http://127.0.0.1:8000/docs`.
2. `/predict` на 2–3 вопросах (налоговый вычет, подушка безопасности, ETF) — показать ответ и источники.
3. Через `/search` показать, как меняется выдача при `method=bm25` / `dense` / `hybrid`.
4. Ноутбук `02_retrieval_experiments.ipynb` — таблица и график: гибрид лучше по MRR и nDCG.

## 8. Ограничения и планы

- Корпус небольшой и однородный, поэтому метрики высокие — на реальной большой базе
  понадобятся IVF/HNSW и батч-индексация.
- Экстрактивная генерация ограничена текстом источников; LLM-режим есть, но требует ключа.
- Дальше: добавить reranker, расширить корпус, прикрутить полноценный MLflow и CI.
